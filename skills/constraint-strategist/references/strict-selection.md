# Strict selection filter

Every skill that looks for work, clients or gigs applies this filter. It exists because the owner of this repo works async and written-first, and a role that needs live calls fails no matter how good the match looks on paper.

## Selection processes that pass, best first

1. Written assessment or take-home task.
2. Portfolio review or paid trial.
3. Written interview by email or chat.
4. Recorded video or voice response, done alone with retakes.

A listing passes only if every step of its process is on this list. One live interview anywhere in the process fails it.

## Automatic rejects

| Reject reason | How to spot it |
| --- | --- |
| Live interview or live discovery calls as core work | "phone screen", "video interview", "lead discovery calls", "client-facing workshops" |
| Hand-written code required | "must write Python/JS", "strong with Apps Script", coding test with no AI use allowed |
| Experience the owner does not have | "3+ years", "5 paid client projects", "verifiable references" when the history is shorter |
| Onsite only | a city address and no remote option |
| Language fluency claims that would be false | "C1 spoken English", "native English" |
| Closed, filled, or already applied | check the application tracker before recommending |
| Spoken-language core work in a language not spoken natively | voice acting, call center |

## Soft flags (allowed, but say so)

- Client with unverified payment or no hire history.
- More than 50 proposals already.
- Pay below the owner's floor.
- Posting older than 30 days.

## Output format for any screening

| Listing | Process steps | Pass / fail | Reason | Link |

A screening that recommends a listing must name its selection process. "Unknown" is allowed and counts as a soft flag, never a pass.
