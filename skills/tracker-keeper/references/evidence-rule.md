# Evidence rule

Every claim about a project, a result, a skill or a person points to proof. No proof, no claim.

Why it matters: in the US, the FTC rule on reviews and testimonials (in force since 21 October 2024) bans testimonials that misrepresent the reviewer's experience, with penalties up to $51,744 per violation. Outside the law, one claim a buyer can disprove ends the conversation.

## What counts as proof

| Claim type | Acceptable proof | Not enough |
| --- | --- | --- |
| "I built X" | Live URL, repo, screenshot with date, run log | A description of X |
| "It handles failure Y" | Test run ID or screenshot of the failure and the result | "It should handle Y" |
| "It saved Z hours" | Before and after measurement with method | An estimate presented as a result |
| "Clients use it" | Client name with permission, or invoice | Demo users, test data |
| A number | Its source, opened and checked | A search snippet |
| A date about the owner | The profile: self-directed since April 2026 | Memory or a guess |

## Wording must match the proof

| Proof you have | Words you may use | Words you may not use |
| --- | --- | --- |
| Built on test data | "built and tested", "demo" | "used by clients", "in production" |
| One test run | "passed in one test run" | "reliable", "proven" |
| Fictional client in a demo | "a demo for a plumbing business" | the fictional name presented as real |
| No paying client yet | "early stage" | "trusted by", "helped businesses" |

## When proof is missing

Turn the claim into an open question, or cut it. Never fill the gap with a plausible number.
